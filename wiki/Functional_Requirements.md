# Функциональные требования

В данном разделе описаны основные возможности приложения **Project Skebob**, поведение системы в ответ на действия пользователя и сценарии взаимодействия.

## 1. Список функциональных требований

| ID | Требование | Описание |
| :--- | :--- | :--- |
| **FR-01** | Получение данных | Система должна запрашивать случайный факт через внешний API при нажатии кнопки. |
| **FR-02** | Локальное хранение | Система должна сохранять все полученные факты в локальную БД SQLite. |
| **FR-03** | Управление избранным | Пользователь должен иметь возможность добавлять/удалять факты из списка «Избранное» кликом по элементу. |
| **FR-04** | Фильтрация | Система должна обеспечивать фильтрацию списка за последние 24 часа. |
| **FR-05** | Агрегация данных | Система должна рассчитывать и отображать количество записей и максимальную длину текста в текущем списке. |
| **FR-06** | Удаление данных | Пользователь может удалять обычные факты с помощью жеста (свайп вправо). |
| **FR-07** | Защита избранного | Система должна блокировать удаление фактов из списка избранного при попытке свайпа. |

## 3. Текстовые сценарии использования

### UC-1: Получение нового факта
*   **Актер:** Пользователь.
*   **Предусловие:** Наличие интернет-соединения.
*   **Основной поток:**
    1. Пользователь нажимает кнопку «Загрузить факт».
    2. Приложение отправляет запрос к API.
    3. Приложение получает JSON-ответ.
    4. Новый факт записывается в БД и отображается вверху списка.
*   **Пост-условие:** Статистика агрегации (счетчик и макс. длина) обновляется автоматически.

### UC-2: Управление статусом «Избранное»
*   **Актер:** Пользователь.
*   **Основной поток:**
    1. Пользователь нажимает на карточку факта в общем списке.
    2. Приложение обновляет флаг `is_favorite` в БД.
    3. На карточке появляется индикатор (звездочка).
    4. Факт становится доступен во вкладке «Избранное».
*   **Альтернативный поток:** Если факт уже был избранным, повторное нажатие снимает этот статус.

### UC-3: Удаление факта свайпом
*   **Актер:** Пользователь.
*   **Основной поток:**
    1. Пользователь делает жест «свайп вправо» на элементе списка.
    2. Приложение проверяет статус `is_favorite`.
    3. Если статус `false`, запись удаляется из БД и списка.
*   **Исключительная ситуация:** Если статус `true`, приложение возвращает карточку на место и выводит уведомление о запрете удаления.
